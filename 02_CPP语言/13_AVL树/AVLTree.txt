// AVLTree 高度平二叉搜索树。
// 1. 搜索二叉树
// 2. 要求树的左右子树的高度差不超过1,左子树和右子树也满足高度差不超过1
//     (当前树和其左右子树都满足前面的要求。)

// 为了方便实现,我们在每一个节点引入一个平衡因子(这里只是为了方便实现,并不是必须的)
// 平衡因子 = 右子树的高度 - 左子树的高度
// 这样,平衡因子可能的取值为 -1,0,1

// 这样这棵树的高度可以控制在 O(logN) 的范围内,从而保证了查找的效率。
// AVL树的增删改查的时间复杂度都是 O(logN)


// 1. 二叉树搜索树 ==> 存储数据的同时方便进行高效的搜索(在此之前的数据结构的搜索基本都是暴力的搜索)
// 问题: 极端情况下(比如有序的方式进行插入),二叉搜索树就会退化成单链表,效率变成O(N),效率低下。

// 2. AVL树在二叉搜索树的基础之上,加了一个条件：左右子树的高度差不超过1,并且左右子树也满足这个条件。(也就是说所有的子树都满足)
// (高度平衡的二叉搜索树)：增删改查的效率非常的高,时间复杂度都是O(logN)。

// 查和改:
//     1. 搜索树中的key是不允许修改的,因为如果修改了整棵树就可能被破坏了。key/value的模型下可以修改value.
//     2. 查和改的和二叉搜索树是一样的。


// ============================================================================
// AVL树的插入
// ============================================================================
// 1. 按照二叉搜索树的规则进行插入。
// 2. 更新平衡因子。
// 3. 如果更新完了,没有出现违反规则的,则插入结束。
//    有违反规则的,则进行旋转处理。

// 更新平衡因子的详细规则:
// a: cur是parent的左子树,则parent->_bf--,如果cur是parent的右子树,则parent->_bf++
// b: 更新完以后,如果parent->_bf == 0,表示parent的高度没有变,后面就不会影响上面的祖先了。
//    (解释:更新前,parent的bf是1或者-1,现在变成了0,说明把矮的那一边填上了;说明我的高度不变,对上一层没有影响)
// c: 更新完parent的bf,如果parent->_bf == 1或者-1,说明parent的高度变高了,继续往上更新。
//    (说明更新前,parent的平衡因子是0,现在变成了1或者-1,说明变高了,对上层有影响)
// d: 更新完parent的bf,如果parent->_bf == 2或者-2,说明parent的子树出现了不平衡,需要旋转处理。

// 插入操作,影响的插入节点的祖先的平衡因子。
// 更新过程中出现了平衡因子为2或者-2的情况,则根据情况判断那种旋转,进行旋转。


// ============================================================================
// AVL树的删除
// ============================================================================
// 1. 按照二叉搜索树的规则进行删除。
// 2. 更新平衡因子。
// 3. 更新过程中出现了平衡因子为2或者-2的情况,则根据情况判断那种旋转,进行旋转处理。


// ============================================================================
// 平衡因子更新规律总结
// ============================================================================
// 第一条:
// 右边插入,父亲平衡因子++;左边插入,父亲平衡因子--
// 右边删除,父亲平衡因子--;左边删除,父亲平衡因子++

// 第二条:
// 插入后,父亲的平衡因子变成0,说明父亲所在的树高度没有变,对上层没有影响,更新结束。
// 删除后,父亲的平衡因子变成0,说明父亲所在的树高度变矮了(把高的那一边删除掉了),对上层有影响,继续往上更新。

// 第三条:
// 插入后,父亲的平衡因子变成1或者-1,说明父亲所在的树高度变高了,对上层有影响,继续往上更新。
// 删除后,父亲的平衡因子变成1或者-1,说明父亲所在的树高度没有变,对上层没有影响,更新结束。

// 第四条:
// 插入/删除后,父亲的平衡因子变成2或者-2,说明父亲所在的树出现了不平衡,需要旋转处理。


// ============================================================================
// 四种旋转场景
// ============================================================================
// 左单旋(RotateL): parent->_bf == 2 且 cur->_bf == 1  (右右模型 RR)
//     1. subR的左边给parent的右边
//     2. parent变成subR的左边
//     --> subR变成根。

// 右单旋(RotateR): parent->_bf == -2 且 cur->_bf == -1 (左左模型 LL)

// 左右双旋(RotateLR): parent->_bf == -2 且 cur->_bf == 1 (左右模型 LR)

// 右左双旋(RotateRL): parent->_bf == 2 且 cur->_bf == -1 (右左模型 RL)


// ============================================================================
// 插入与删除的区别
// ============================================================================
// 插入: 旋转后子树高度恢复,可直接结束更新
// 删除: 旋转后子树高度可能继续变矮,需要继续向上更新
